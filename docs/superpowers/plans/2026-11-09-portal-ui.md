# Portal UI Pass Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the signed-in business and creator portals one clean, white, Clay-like app shell (sidebar, top bar, phone drawer), a home page per role, step-by-step onboarding, the creator directory inside the app, and consistent pages.

**Architecture:** Every portal page moves under one `(portal)` route group whose layout draws `PortalShell` once; onboarding gets its own `(onboarding)` group and shell. Role-dependent chrome (links, name, main action) renders inside `Suspense` from a request-cached viewer lookup, so the static frame paints at once and pages keep streaming their own content. Pure rules (nav, steps, checklist, alerts) live in framework-free `src/lib` modules with `node --test` unit tests; shared UI pieces join the design system.

**Tech Stack:** Next.js 16 App Router (`cacheComponents: true`), React 19, TypeScript strict, Tailwind v4, Lucide icons, Supabase via `src/lib/db/*`, `node --test` for unit tests, pgTAP via `supabase test db`.

**Spec:** `docs/superpowers/specs/2026-11-09-portal-ui-design.md` (read it first; this plan argues from it).

## Global Constraints

- No new dependencies, no migrations, no change to RLS or to what any role can see or do.
- Page background is white everywhere (`canvas` = #FFFFFF, already committed). In the portal, panels are white with `ring-1 ring-hairline`; tinted fills only for callouts, pills, tiles and the active nav item.
- Sidebar appears from `lg` (1024px); below that the top bar has a menu button and a drawer.
- Copy: sentence case, no all-caps, curly apostrophes and quotes (’ “ ”) as in existing copy; never ship unverified numbers.
- Tap targets at least 44px; never remove the focus outline; motion only under `motion-safe:`.
- Pages keep their own `Suspense` + `LoadingNotice` around anything that reads the session (Cache Components requires it).
- Database access only through `src/lib/db/*`; pure modules in `src/lib` import siblings with relative `.ts` paths so `node --test` can load them.
- Every task ends with `npm run lint`, `npm run typecheck` and `npm test` passing, then a commit (imperative message, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`).
- Browser checks: the user's dev server is on port 3030 (never kill it); use `next start -p 3100` for production checks; never run `supabase db reset`; throwaway accounts are `e2e-*@example.com` and are deleted at the end (Task 10). Pages kept mounted by React Activity are hidden: query only visible elements and wait for `[aria-busy=true]` to clear.

## Review Focus

1. **No profile yet, portal URL opened directly** (`/home`, `/business/campaigns`, `/profile`): the shell shows a neutral name, the page redirects to `/onboarding`, nothing crashes. Pinned in Task 3 (browser step).
2. **Going back across the profile-creation step** in creator onboarding: the niches step has no back link, and `/onboarding` sends anyone with a profile to `/home`, so nobody re-creates a profile. Pinned in Task 1 (`stepInfo` test) and Task 5 (browser step).
3. **Publishing from the done step with niches or platforms skipped:** the button is disabled with the reasons listed; a forced submit leaves the profile a draft and returns to `/onboarding/done`. Pinned in Task 5.
4. **Drawer left open while resizing to desktop or after navigating:** it closes and the page scrolls again. Pinned in Task 3.
5. **Very long names** (100-character business name, long display name, long campaign title) in the sidebar, crumbs and tables: truncated with an ellipsis, no sideways scroll at 375px. Pinned in Tasks 3 and 9.
